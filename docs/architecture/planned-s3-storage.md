# 추후 설계안: 정적 웹·감사 로그·앱 로그의 S3 분리

**상태: 미구현 제안.** 서울 정적 웹과 오사카 EC2 감사 로그에 각각 버킷 1개를 제안한다. 오사카에 Loki를 도입해 앱 로그를 장기 보관하기로 하면 버킷 1개를 추가한다. 기존 [Terraform state 버킷](../../infra/STATE.md)은 이 수에 포함하지 않으며, 웹 파일이나 로그 저장소로 재사용하지 않는다.

| 용도 | 제안 리전 | 쓰는 주체 | 읽는 주체 | 분리 이유 |
|---|---|---|---|---|
| Angular 정적 웹 | 서울 `ap-northeast-2` | 승인된 웹 릴리스 작업 | CloudFront(OAC) | 방문자에게 제공할 빌드 산출물이다. 로그와 달리 릴리스 단위로 교체한다. |
| `osaka-observe` EC2 감사 로그 | 오사카 `ap-northeast-3` | 선정한 감사 로그 수집 주체 | 감사 담당자 | 서버 운영자 활동에 대한 증적이다. 앱 운영자에게 삭제·보존 정책 변경 권한을 주지 않는다. |
| 앱 로그 장기 보관 **(선택)** | 오사카 `ap-northeast-3` | Loki | Loki를 통해 Grafana에서 조회 | 장애 분석용 앱 로그다. 감사 증적과 조회 대상·보존 기간이 다르다. |

## ① 서울: CloudFront의 정적 웹 원본

- 화면과 JS·CSS 요청은 **브라우저 → CloudFront → 비공개 S3**로 전달한다. `dist/browser/`의 내용물을 업로드하며 `index.html`은 원본 루트에 둔다. S3 웹사이트 엔드포인트가 아닌 S3 REST 원본에 OAC(Origin Access Control)를 연결하고, 지정한 CloudFront 배포만 웹 파일을 읽도록 제한한다.
- `/petclinic/api/*` 요청은 **CloudFront → 서울 내부 ALB → Spring** 경로로 분리한다. API 오류가 Angular의 `index.html`로 바뀌지 않게 하고, 화면 경로(`/owners/1` 등)에서 새로고침하는 경우만 SPA 진입점으로 처리한다.
- 전환을 검증한 뒤에는 정적 파일 제공만 담당하던 Nginx WEB Pod·Service·ALB 웹 대상 그룹이 필요 없다. 이 제안은 현재 배포 정의를 변경하거나 삭제하지 않는다.

## ② 오사카: 관제 EC2 감사 로그

먼저 어떤 질문에 답할지 정한다. ‘누가 SSM 세션을 열고 닫았는가’는 CloudTrail 이벤트, ‘일반 SSM 셸에서 어떤 명령과 출력이 오갔는가’는 Session Manager 세션 로깅, ‘호스트에서 어떤 OS 이벤트가 발생했는가’는 `auditd` 규칙과 수집기 설정에 해당한다. SSH·포트포워딩 방식의 SSM 세션은 세션 내용 로깅 대상이 아니다. **버킷만 만들어서는 이 기록이 수집되지 않는다.**

수집 주체에는 필요한 경로의 쓰기 권한만, 감사 담당자에게는 조회 권한을 준다. 보존 정책 관리는 별도 역할로 분리한다. 실제 보존 기간, 민감정보 처리, 삭제 방지(Object Lock 필요 여부)는 감사 요건을 확인한 뒤 결정한다.

## ③ 오사카: OpenTelemetry 앱 로그와 Loki (선택)

**수집:** 앱 → OpenTelemetry Collector → Loki → S3. **조회:** Grafana → Loki → S3. S3는 Loki의 저장소이지 Grafana가 로그 파일을 직접 검색하는 곳이 아니다. 이 경로를 선택하면 같은 앱 로그를 Collector에서 다른 S3 버킷으로 다시 보낼 필요가 없다. Prometheus의 메트릭 저장과 Collector 자체의 운영 로그는 이번 앱 로그 버킷의 범위가 아니다.

## 구현 전 결정할 사항

- 웹: 배포 주체와 캐시 정책을 정하고, S3 직접 접근 차단·SPA 새로고침·API 오류 보존을 각각 검증한다.
- 감사: 수집할 이벤트와 보존 기간을 정하고, 샘플 기록이 도착하는지와 수집 역할로 삭제할 수 없는지를 확인한다.
- 앱 로그: 장기 보관이 필요한지 먼저 결정한다. 필요하면 수집 경로의 인증·암호화, 리전 간 전송량, Loki 보존 정책을 정하고 Grafana에서 테스트 로그를 조회한다.

버킷명·IAM 정책·수명 주기와 배포 일정은 확정하지 않았다. 구현은 별도 PR에서 검토한다.
