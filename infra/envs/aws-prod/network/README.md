# 서울 서비스망·관리망

- 서비스 VPC 1(`10.10.0.0/22`): 앱·DB·퍼블릭 서브넷과 NAT를 관리한다.
- 관리 VPC 2(`10.20.0.0/24`): 서울 2a 비공개 서브넷 `10.20.0.0/27`, 로컬 전용 라우팅 테이블과 연결만 구성한다. 루트 출력 `management_vpc_id`와 `management_subnet_id`는 서울을 가리킨다. 이전에 삭제한 VPC와 CIDR은 같지만 ID는 새로 할당된다.
- [오사카 관제망](../OSAKA-VPC2.md)(`10.40.0.0/16`)은 별도이며 `osaka_observe`로 조회한다. 오사카에는 향후 호스트를 위한 SSM IAM 구성이 있다.

서울 관리 EC2·SSM 엔드포인트·EKS 관리용 443 규칙·서울 VPC 1↔2 피어링은 이번 단계에 없다. 향후 서울 EKS를 관리하려면 승인된 호스트, IAM, SSM 통신 경로와 비공개 API 왕복 라우팅을 별도로 구성한다.
